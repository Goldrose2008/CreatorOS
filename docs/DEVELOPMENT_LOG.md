# Журнал разработки CreatorOS

## Временные решения:
	1. В MVP фактически используется один пользователь; структура должна позволять добавить командную работу позднее.
	2. Сущность Series откладывается до отдельного этапа и не входит в первую рабочую версию.
	3. Platform / Account / Publication, расширенная Analytics, Team, AI и сложная Automation откладываются до соответствующих этапов.
	4. Система статусов пока может изменяться до появления общей универсальной модели статусов.
	5. Технические детали миграции SQLite могут уточняться до перехода к окончательной системе последовательных миграций.
	6. Набор конкретных React/Electron пакетов и инфраструктурных библиотек будет окончательно определён в ходе миграции; зависимости не должны добавляться без практической необходимости.

## 30.09.2026

### Пересмотр технологического решения
	✅ После дополнительного сравнения технологических стеков и с учётом будущей роли API-интеграций принято новое окончательное решение: CreatorOS разрабатывается по варианту B — TypeScript + React + Electron.
	✅ CSS становится основным средством оформления интерфейса; общие стили, темы и дизайн-токены организуются централизованно, а уникальные стили страниц и компонентов хранятся рядом с владельцами.
	✅ Electron выбран как desktop-shell для Windows, macOS и Linux.
	✅ Vite допускается сохранить как существующий инструмент сборки React renderer-части, поскольку смена сборщика не является целью технологического перехода.
	✅ API и интеграции с внешними площадками признаны фундаментальным архитектурным слоем CreatorOS: предусматриваются OAuth, загрузка материалов, публикация, статусы и получение статистики в пределах возможностей конкретных площадок.
	✅ Для каждой площадки будет использоваться отдельный интеграционный адаптер, скрывающий конкретный API от UI.
	✅ SQLite сохраняется как локальная БД; доступ к ней будет проходить через сервисный/репозиторный слой Electron/Node.js.
	✅ Архитектура должна быть совместима с будущим вариантом C: при необходимости тяжёлые операции можно будет вынести в C++ или Rust через отдельный native bridge.
	✅ На первом этапе реализуется только тёмная тема; светлая тема и переключение между темами откладываются.
	✅ Предыдущее решение о C# + .NET + Avalonia считается отменённым и заменяется решением TypeScript + React + Electron.

	✅ Tauri, src-tauri, Rust-код Tauri и Tauri-specific конфигурация должны быть удалены или заменены на Electron.

	✅ Лишний, устаревший или дублирующий код удаляется после аудита.
	Результат: утверждён новый технологический и миграционный путь CreatorOS; до начала переделки кода необходимо сначала проверить структуру legacy-react-tauri и составить точный план преобразований.
