# Журнал разработки CreatorOS

## Правила разработки CreatorOS
* Все изменения выполняются постепенно и осознанно.
* Перед изменением существующего кода необходимо проверить текущую архитектуру, TECHNICAL_SPEC и DEVELOPMENT_LOG.
* Полная перезапись файлов без необходимости запрещена. Предпочтительный формат изменений — точечные исправления с указанием места изменения.
* Архитектурные решения сначала обсуждаются, затем реализуются.
* После каждого крупного этапа выполняются проверка работоспособности, commit, push и запись в DEVELOPMENT_LOG (журнал разработки).
* Технические данные программы, архитектурные правила записываются в TECHNICAL_SPEC.

* CreatorOS развивается как desktop application на стеке C++20 + Qt 6 + CMake + SQLite + HTML/CSS + минимальный JavaScript.
* C++ является основой текущей архитектуры; native-слой больше не является будущим вариантом, а является основной реализацией приложения.

* Все CSS-файлы хранятся только в `src/styles/` и его подкаталогах.
* Общие стили, дизайн-токены, типографика, темы и состояния хранятся централизованно.
* Уникальные (используемые единожды) стили компонента или страницы также хранятся в `src/styles/` в соответствующем разделе ответственности; CSS-файлы рядом с `.tsx` не создаются.
* Не создавать отдельные стили без необходимости.

* Сохранять уже принятые удачные решения.
* Не усложнять архитектуру заранее.
* Каждое новое расширение должно учитывать будущие возможности:
  * API-интеграции;
  * публикации на внешние площадки;
  * автоматизацию;
  * командную работу;
  * возможное подключение native-модулей.


## Временные решения:

## 01.10.2026
### Пересмотр технологического стека и архитектуры
- Подтверждён переход с текущей Electron/React/TypeScript-реализации на целевой стек C++20 + Qt 6 + CMake + SQLite + HTML/CSS + минимальный JavaScript.
- Обновлён `docs/TECHNICAL_SPEC.md` до версии 1.1.
- Зафиксирована новая архитектура: Qt Widgets + QWebEngineView для desktop-shell/web renderer, QWebChannel для ограниченного C++ ↔ Web UI bridge, C++ domain/application/infrastructure/integration слои, SQLite через Qt SQL/QSQLITE.
- Зафиксированы лицензионные требования: LGPL-совместимый набор Qt-модулей, динамическое распространение Qt, license/source notices, отдельная проверка GPL-only модулей и third-party лицензий Qt WebEngine.
- Legacy React/TypeScript/Electron/Tauri/Rust-структура сохраняется только как исходный материал для миграции; текущей целевой архитектурой она не является.
- Фактическая миграция исходного кода ещё не выполнена; на этом этапе обновлена архитектурная документация и структура целевой системы.

Рабочий прототип C++/Qt: приложение успешно собирается и запускается; Qt WebEngine загружает HTML/CSS, а обмен C++ ↔ JavaScript через QWebChannel работает. Настроен IntelliSense для Qt-заголовков.
