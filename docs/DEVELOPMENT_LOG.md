# Журнал разработки CreatorOS

## Временные решения:
	1. В MVP фактически используется один пользователь; структура должна позволять добавить командную работу позднее.
	2. Сущность Series откладывается до отдельного этапа и не входит в первую рабочую версию.
	3. Platform / Account / Publication, расширенная Analytics, Team, AI и сложная Automation откладываются до соответствующих этапов.
	4. Система статусов пока может изменяться до появления общей универсальной модели статусов.
	5. Технические детали миграции SQLite могут уточняться до перехода к окончательной системе последовательных миграций.
	6. Набор конкретных Avalonia Controls и вспомогательных NuGet-пакетов будет окончательно определён в ходе создания чистого проекта; они не должны становиться обязательной архитектурной зависимостью без необходимости.

## 29.09.2026

### Принято решение о смене технологического стека
	✅ Принято окончательное решение не продолжать React/Tauri-прототип.
	✅ Новая версия CreatorOS будет разрабатываться на C# + .NET 10 LTS + Avalonia UI.
	✅ Выбор сделан в пользу классической объектно-ориентированной модели C#: наследование, virtual/override, свойства, методы и события напрямую соответствуют принятому архитектурному «принципу ООП».
	✅ Avalonia выбрана для сохранения одной кроссплатформенной desktop-кодовой базы под Windows, macOS и Linux.
	✅ Для SQLite выбран Microsoft.Data.Sqlite.
	✅ React, TypeScript, Vite и Tauri не переносятся в новую кодовую базу.
	✅ Бизнес-модель CreatorOS и ранее принятые предметные правила сохраняются и переносятся на новый технологический стек.
	Результат: принято направление новой реализации CreatorOS с чистой кодовой базой.
